# Technical Reflection — Bank + Generation Rule

Produces learning data, not feelings reports. Answer specifically.

The builder NEVER pastes the bank verbatim. Digest the session and
write 4–6 grounded prompts citing exercise IDs, actual mistakes, and
decisions faced — plus the two anchors below.

---

# Anchors (always include)

## Hint dependency this session

Exercises at level 0 (no hints):        Level 1–2:        Level 3+:

## Transfer check

Which concept from a previous lesson did you use, unprompted, and where
would it break if removed?

---

# Bank (adapt, don't paste — ground each in this session's events)

- What decision did you make? Why that approach? What alternative did
  you consider (and what killed it)?
- Which bug took the longest to diagnose? What misunderstanding caused
  it — quote the exact wrong belief?
- What would you change if requirements changed (name the requirement
  change concretely)?
- What could you implement fully independently next time — and what
  single gap blocks that today?
- Which spec sentence misled you, if any — how should it have read?
- Which review finding stung most — was it fog or difficulty?
