# Testing Handbook

Testing increases confidence.

Testing does not prove software is perfect.

Status: SUPPORTING until Stage 3, where testing (pytest) becomes CORE.
Until then, practice the mindset manually: before running code, predict
the edge cases that would break it.

---

# What Should Be Tested

Normal cases

Edge cases

Invalid input

Empty input

Unexpected values

Boundary conditions

---

# Good Test Characteristics

Independent

Repeatable

Readable

Fast

Focused

---

# Test Mindset

Assume users will use your software incorrectly.

Design tests accordingly.

---

# Common Mistakes

Testing implementation instead of behavior.

Writing one huge test.

Ignoring edge cases.

Not testing failures.
