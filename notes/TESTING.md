# Testing Handbook

Testing increases confidence.

Testing does not prove software is perfect.

Status: CORE from Stage 3 onward. In Stage 4, tests live at the API
boundary and the suite must run from a clean checkout.

---

# What Should Be Tested

Normal cases

Edge cases

Invalid input

Empty input

Unexpected values

Boundary conditions

---

# Good Test Characteristics

Independent

Repeatable

Readable

Fast

Focused

---

# Test Mindset

Assume users will use your software incorrectly.

Design tests accordingly.

---

# Common Mistakes

Testing implementation instead of behavior.

Writing one huge test.

Ignoring edge cases.

Not testing failures.
