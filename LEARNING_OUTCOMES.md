# Learning Outcomes (V2)

This document defines the competencies required to complete the Python
phase of the Learning OS.

The curriculum is designed backward from these outcomes.

Completing lessons does not guarantee mastery. Only demonstrated
competence counts.

---

# Goal

Upon completing the Python roadmap, the learner thinks and works like a
junior software engineer who is fully prepared to begin Applied AI
Engineering — able to build real software independently, not merely
recall syntax.

---

# The Capability Ladder

Every CORE topic must climb this ladder. Outcomes are stated in terms of
this progression:

```text
I know the syntax.
↓
I understand the concept.
↓
I can implement it.
↓
I can combine it with other concepts.
↓
I can debug it.
↓
I can make engineering decisions around it.
↓
I can build something useful independently.
```

---

# Core Competencies

## Problem Solving

The learner can

- Break complex problems into smaller parts.
- Design solutions before writing code.
- Explain their reasoning clearly.
- Choose data structures from guarantees, not habit.
- Identify edge cases before they become bugs.

---

## Python Core (Stage 1) ✅

The learner can confidently use variables and references, data types,
control flow, collections, functions, modules, and basic CLI patterns —
combining them across exercises without relying on AI.

---

## Python Application (Stage 2)

The learner can build a multi-file, persistent, validated application:

- Handle failures with exceptions instead of crashes.
- Read/write files, JSON, and CSV safely with pathlib.
- Structure code across modules and packages.
- Apply functions across module boundaries.
- Use basic type hints as documentation.
- Use OOP practically — classes, composition, inheritance basics — and
  recognize when OOP is unnecessary.
- Use Git continuously as part of the workflow.

Evidence: the Expense / Transaction Manager stage project.

---

## Python Engineering (Stage 3)

The learner can work like an engineer on their own code:

- Debug systematically (traceback → hypothesis → test → fix → explain).
- Test with pytest.
- Log instead of print-debugging.
- Consume HTTP APIs with requests.
- Structure a professional project.
- Recognize decorators, generators, iterators, context managers, regex,
  and datetime in real code and apply them where they fit.

Evidence: the Automation / Data Processing Toolkit stage project.

---

## Python for AI Engineering (Stage 4)

The learner is ready to build AI-adjacent services:

- Validate data with Pydantic.
- Serve APIs with FastAPI.
- Manipulate data with NumPy and Pandas fundamentals.
- Persist with SQL fundamentals (SQLite; SQLAlchemy as needed).
- Architect a project the way a team would.

Evidence: the AI Dataset Manager / AI Service stage project.

---

## Software Engineering (Cross-Cutting)

The learner can

- Read unfamiliar code and reason about it.
- Refactor working code into good engineering code.
- Debug independently using a repeatable protocol.
- Write readable, maintainable, Pythonic code.
- Explain technical decisions and trade-offs.
- Learn new libraries from documentation without an instructor.

---

## Interview Readiness (Parallel Track)

The learner can solve common interview problems (arrays, strings, hash
maps, sets, two pointers, sliding window, stack/queue, binary search,
basic recursion) and verbally explain complexity trade-offs between
brute force and optimized approaches.

---

# Graduation Criteria

The Python phase is complete only when the learner has:

- Reached target mastery for every CORE topic (Level 4).
- Reached Level 3 for every SUPPORTING topic.
- Completed all four stage projects independently.
- Passed formal code reviews on those projects.
- Demonstrated transfer: old concepts appearing unannounced in new
  solutions.
- Built at least one medium-sized application from scratch and explained
  every major implementation decision in it.

Not: lessons checked off. Evidence produced.
