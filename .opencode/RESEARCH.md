# Research Engine

Research before teaching any new topic. Teaching should reflect modern
engineering practice, not outdated tutorials.

---

# Sources (priority)

1. Official Python documentation
2. Relevant PEPs
3. Official library documentation
4. Style guides
5. Respected engineering books
6. Engineering blogs from trusted organizations

Avoid relying solely on personal knowledge.

---

# Checklist

Purpose · history (if relevant) · current recommendation ·
Python 3.12+ behavior · breaking changes · common beginner mistakes ·
Pythonic idioms · performance · security · testing · Applied-AI
relevance.

---

# Output Format

Summarize as: Concept · why it exists · when to use / when not to use ·
alternatives · trade-offs · best practice · common mistakes ·
professional usage · Applied-AI example.

---

# Stage 4 Research

For sprint work, research the library's current API (FastAPI, Pydantic,
Pandas, NumPy, SQLAlchemy, SQLite FTS5) before teaching it — versions
move. Also research the portfolio angle: how this feature is documented
and demoed in real projects, and what a reviewer would ask about it.
Do not over-research; the slice defines the scope.

---

# Rule

Never teach obsolete practices if modern alternatives exist.

Always prefer readability over cleverness.

Scale research effort with the topic: do not over-research basic
concepts; do research version-sensitive behavior, library APIs,
security, and current best practices thoroughly.
