## Type

`[REAL-WORLD]` Stage 4 portfolio sprint

## Goal (one sentence)

Accept an uploaded LLM dataset file, validate every record against a
Pydantic schema, and return a structured validation summary with
OpenAPI docs available.

## Demo (definition of done)

Start the API (exact command is yours to define and document), then:

```text
curl -F "file=@sample.jsonl" http://127.0.0.1:8000/datasets/validate
```

Returns HTTP 200 with a JSON summary: total rows, valid count, invalid
count, and per-row errors (`row`, `field`, `message`). `GET /docs`
loads and shows the endpoint.

## Scope

In scope:

- [ ] Upload endpoint accepting a JSONL or JSON-array dataset file.
- [ ] Pydantic v2 schema for one record: `instruction` (required,
      non-empty str), `response` (required, non-empty str), optional
      `input` (str).
- [ ] Validate every row; collect per-row errors instead of stopping at
      the first bad row.
- [ ] Structured validation summary (counts + error list).
- [ ] Honest 4xx for empty, malformed, or unsupported uploads.
- [ ] OpenAPI `/docs` reflects the real contract.
- [ ] Boundary tests green (success + each error path).

Out of scope (explicitly deferred):

- Cleaning/repairing data, quality scoring, export (A2).
- Persistence / SQLite (A3).
- Docker, CI, auth, deployment.

## API contract

| Method | Path | Request | Response | Errors |
|--------|------|---------|----------|--------|
| POST | `/datasets/validate` | multipart `file` (`.jsonl` or `.json`) | `200` summary: `{total, valid, invalid, errors:[{row, field, message}]}` | `400` empty/malformed file · `415` unsupported content type |
| GET | `/docs` | — | OpenAPI UI | — |

The learner may refine names/shape in the slice plan; the contract must
stay honest (validation errors are 4xx, never 500, no tracebacks to
clients).

## Acceptance criteria

- [ ] Server boots; `GET /docs` loads.
- [ ] Valid file → correct `total`/`valid`/`invalid` counts.
- [ ] Rows with missing/empty/wrong-typed fields are reported per row.
- [ ] Empty file → `400`; malformed JSON → `400`; unsupported type →
      `415`. No `500` for expected input problems.
- [ ] Response model is a Pydantic schema, not a raw dict.
- [ ] Tests green from a clean checkout.
- [ ] Demo command documented in README.
