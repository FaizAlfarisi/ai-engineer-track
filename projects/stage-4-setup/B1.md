## Type

## Goal (one sentence)

Accept an uploaded document, split it into deterministic chunks, persist
the document and chunk metadata in SQLite, and return the ingest result.

## Demo (definition of done)

Start the API (exact command is yours to define and document), then:

```text
curl -F "file=@sample.txt" http://127.0.0.1:8000/documents
```

Returns HTTP 201 with `{document_id, filename, chunk_count}`. Then:

```text
curl http://127.0.0.1:8000/documents/<document_id>
```

Returns the document with its chunks in order. `GET /docs` loads.

## Scope

In scope:

- [ ] Ingest endpoint accepting a plain-text / Markdown document.
- [ ] Deterministic chunking: chunk indices start at 0, are contiguous,
      no empty chunks, and the same input yields the same chunks.
- [ ] SQLite persistence: document row + chunk rows (your schema).
- [ ] Fetch endpoint returning a document and its ordered chunks.
- [ ] Honest 4xx for empty, malformed, or unsupported uploads; 404 for
      unknown document id.
- [ ] Parameterized SQL only.
- [ ] OpenAPI `/docs` reflects the real contract.
- [ ] Tests green (success + each error path + temp DB).

Out of scope (explicitly deferred):

- Keyword search / FTS5 / `SearchBackend` (B2).
- SQLAlchemy / ORM (B2).
- Paging (B2), Docker, CI, auth, deployment.

## API contract

| Method | Path | Request | Response | Errors |
|--------|------|---------|----------|--------|
| POST | `/documents` | multipart `file` (`.txt` / `.md`) | `201` `{document_id, filename, chunk_count}` | `400` empty/malformed · `415` unsupported type |
| GET | `/documents/{id}` | path `id` | `200` document + ordered `chunks` | `404` unknown id |
| GET | `/docs` | — | OpenAPI UI | — |

The learner may refine names/shape in the slice plan; the contract must
stay honest (validation errors are 4xx, never 500, no tracebacks to
clients).
